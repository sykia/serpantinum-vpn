# Адаптеры и устройство модуля

## Текущая реализация

`overlay/` содержит новые компоненты и три изменённых файла upstream:

- `BarModuleRegistry.qml`: регистрация типа `vpn` и его face.
- `WindowRegistry.js`: popup, размеры и пункт launcher.
- `BarGeneralTab.qml`: VPN в настройках панели.
- `vpn/VpnStatus.qml`: опрос состояния и обработка явного клика пользователя.
- `vpn/VpnPopup.qml`: визуальная основа из сетевого окна Serpantinum.
- `vpn/VpnLocations.qml`: список, поиск, задержки и сортировка.

Python использует стандартную библиотеку. `vpn-status.py` читает выбранный сервер
и проверяет cmdline процессов Happ Xray. `vpn-control.py` вызывает клиент только
по действию пользователя. `vpn-autostart.py` готовит три login preference-ключа
и запускает GUI после входа в сессию.

`vpn-locations.py` читает SQLite в режиме read-only, передаёт зашифрованную строку
декодеру `happ-read.cjs` через stdin и получает метаданные. Node.js использует
встроенные fs/crypto; npm-пакеты не нужны. Совместимость декодера ограничена
ELF x86_64 / внутренним расположением данных Happ 4.4.8. Это не публичный API Happ.

В output декодера входят id, subscriptionId, guid, name, host, port и subscription.
Токены, пароли и полные конфигурации не выводятся. Адреса серверов нужны для
TCP-проверки и остаются в локальном кэше. Никакой телеметрии модуль не отправляет.
Проверка задержки соединяется с серверами пользователя через текущую сеть.

## Подключение другого VPN

Сам интерфейс подходит для другого клиента, но готового универсального переключателя
пока нет. Чтобы добавить клиент, нужно реализовать backend и связать его с QML.
Предлагаемый контракт:

```json
{
  "connected": true,
  "state": "connected",
  "location": "Germany",
  "serverId": "example-id",
  "capabilities": {
    "locations": true,
    "ping": true,
    "selectLocation": false
  }
}
```

Операции: `status`, `connect`, `disconnect`, `open`, `locations`, `probe`.
Передавать команды нужно аргументами subprocess, без shell-конкатенации.
Если клиент не предоставляет программный выбор локации, оставьте открытие его GUI.
Неподдерживаемые возможности следует скрывать или объяснять в интерфейсе.

Это направление развития, а не обещание поддержки любого VPN в релизе 0.1.0.
Не считайте одно наличие процесса доказательством подключения: для других backend
желателен API с connecting/reconnecting/error и отдельной проверкой доступности.

## Ограничения для разработки

`VpnPopup.qml` сохраняет часть неиспользуемой логики исходного NetworkPopup.
Перед большой переработкой лучше выделить общий визуальный компонент.
Вертикальная face пока повторяет горизонтальную и требует отдельной проверки.
Большинство добавленных строк интерфейса пока на русском.

Тесты выполняются без выключения действующего VPN:

```bash
python3 -m unittest discover -s tests -v
node tests/test-happ-adapter.cjs
```

Для полного integration-теста installer задайте `SERPANTINUM_TEST_SOURCE` на
`src` поддерживаемой upstream-ревизии. Без него этот один тест будет пропущен.
CI загружает три upstream-файла фикстуры и запускает тест в изолированном HOME.

## Локальное управление Happ 4.4.8 (0.2.0, экспериментальное)

`native/happ-bridge.cpp` — необязательная библиотека Qt 6, загружаемая в Happ при
его обычном запуске. Через обработку событий QObject она обнаруживает TMainObject
и создаёт пользовательский Unix-сокет в XDG_RUNTIME_DIR. Опрос `status` только
подтверждает готовность. Команда `select` вызывает собственный метод Happ
`startServer(int subscriptionId, int serverId)` в главном потоке; ID могут быть
отрицательными, так как Happ использует signed int. Другие действия отклоняются.
Python проверяет существование пары ID в базе и не отправляет повторный выбор.

Нет внедрения в уже работающий процесс, записи базы, gdb/ptrace, эмуляции кнопок
или самостоятельного управления Xray. При запуске библиотека не меняет соединение.
Qt6Core проверяется перед загрузкой; несовпадающий адаптер пропускается.
Метод и класс являются внутренними интерфейсами Happ, поэтому совместимость
ограничена указанной версией. Тест использует отдельный QObject с тем же методом;
переключение реального VPN намеренно не выполнялось.
