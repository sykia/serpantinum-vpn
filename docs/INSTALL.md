# Установка и восстановление

## Перед началом

Нужны Linux с Wayland, рабочие Serpantinum и Happ, Python 3, Node.js, Bash и Quickshell.
Модуль не устанавливает сам VPN-клиент, подписку или системные сетевые службы.
Сначала убедитесь, что Happ самостоятельно подключается к импортированному серверу.

Релиз 0.1.0 рассчитан на Serpantinum 2.2.5-1, ревизию
`a304a330e4a32ab78f491a02fb9b4b06672d1760`, и Happ 4.4.8 Linux x86_64.
Более новые версии не объявляются совместимыми автоматически.

Запускайте установщик **без sudo**, из своей графической сессии. Не запускайте его от root.
Установщик не вызывает disconnect, stop, restart, reboot или logout.
Для проверки перед изменениями используйте `bash install.sh --dry-run`.

## Получить дополнение

```bash
git clone https://github.com/sykia/serpantinum-vpn.git
cd serpantinum-vpn
```

Или скачайте архив релиза, распакуйте его и откройте терминал в распакованной папке.
Установщик работает локально из содержимого архива: `curl | bash` не нужен.

## Arch Linux

Установите Serpantinum по [инструкции автора](https://github.com/ilyamiro/serpantinum#installation),
а Happ — из [официального репозитория](https://github.com/Happ-proxy/happ-desktop).
Не меняйте работающий клиент лишь ради этого дополнения; учитывайте таблицу совместимости.

```bash
sudo pacman -S --needed python nodejs git
bash install.sh --dry-run
bash install.sh
```

Serpantinum из официального установщика обычно находится в
`~/.local/share/serpantinum/src`. Этот путь и `/usr/share/serpantinum` определяются автоматически.
Если автоопределение не подошло:

```bash
bash install.sh --source "$HOME/.local/share/serpantinum/src" --dry-run
bash install.sh --source "$HOME/.local/share/serpantinum/src"
```

Путь к GUI Happ может отличаться между пакетами. `--happ` — команда запуска;
`--happ-binary` — сам большой ELF-файл приложения, обычно с именем `Happ`.
Установщик пробует путь из работающего процесса, из wrapper и несколько обычных директорий.
Для собственного расположения:

```bash
bash install.sh --happ /path/to/happ --happ-binary /path/to/Happ --dry-run
bash install.sh --happ /path/to/happ --happ-binary /path/to/Happ
```

Полноценная проверка в реальной Arch-сессии пока не проведена. Проверены upstream-структура
файлов, переносимые пути, установка в изолированный HOME и создание launch-скриптов.

### Если версия установленного Serpantinum отличается

Не обходите проверку и не заменяйте три QML-файла вручную. Можно подготовить
отдельный checkout поддерживаемой версии, сохранив обычный пакет:

```bash
git clone https://github.com/ilyamiro/serpantinum.git ../serpantinum-base
git -C ../serpantinum-base checkout a304a330e4a32ab78f491a02fb9b4b06672d1760

bash install.sh \
  --source ../serpantinum-base/src \
  --daemon ../serpantinum-base/bin/serpantinumd \
  --cli ../serpantinum-base/bin/serpantinum \
  --dry-run
```

Убедитесь, что зависимости upstream уже установлены и `quickshell` доступен в PATH.
Затем повторите команду без `--dry-run`. Установщик копирует исходные shell-скрипты
запуска в снимок; удаление checkout после успешной установки не ломает их.
Это запускает старую совместимую копию оболочки при следующем входе, поэтому отдельные
настройки более новой оболочки могут быть ей неизвестны. Сохраните свои настройки заранее.

## NixOS

Сам Serpantinum должен быть установлен по [NixOS-инструкции проекта](https://github.com/ilyamiro/serpantinum#nixos).
Поддерживаемую ревизию можно зафиксировать входом flake:

```nix
inputs.serpantinum.url = "github:ilyamiro/serpantinum/a304a330e4a32ab78f491a02fb9b4b06672d1760";
```

Изменения системной конфигурации и rebuild не выполняются установщиком дополнения.
Не применяйте системные изменения, которые могут перезапустить ваш текущий VPN,
если соединение сейчас нельзя прерывать.

Запуск с Python и Node.js:

```bash
nix shell nixpkgs#python3 nixpkgs#nodejs --command bash install.sh --dry-run
nix shell nixpkgs#python3 nixpkgs#nodejs --command bash install.sh
```

Установщик читает метаданные makeBinaryWrapper без исполнения shell-текста,
сохраняет Qt/QML/PATH-окружение и обходит принудительный SERPANTINUM_DIR исходного wrapper.
Пути вашей системы генерируются при установке; в опубликованных исходниках нет
путей чужого `/nix/store` или `/home/desktop`.

GC roots сохраняют исходный пакет Serpantinum, Happ, Python и Node.js.
Поэтому snapshot переживает `nixos-rebuild` и сборку мусора. Он не получает
изменения интерфейса из новых пакетов автоматически.

### Home Manager и декларативные настройки

Если `settings.json` управляется Home Manager, установщик сохраняет исходную ссылку,
но создаёт редактируемый пользовательский файл. Следующая активация Home Manager может
восстановить декларативную версию. Добавьте `"vpn"` также в декларативный список модулей:

```nix
programs.serpantinum.settings.bar.modules.right = [ "tray" "wifi" "vpn" "vol" "bat" ];
```

Сохраните нужные элементы своей существующей панели. Не заменяйте весь список этим
примером, если у вас другой состав. Локальный systemd drop-in обычно имеет приоритет
над системной unit, но декларативное управление самим drop-in может его заменить.
Оставьте `vpn-addon.conf` пользовательским либо перенесите его содержимое в Home Manager.

## Что меняет установщик

| Путь | Назначение |
| --- | --- |
| `$XDG_DATA_HOME/serpantinum-vpn` | Снимок всей совместимой оболочки с дополнением |
| `~/.local/bin/serpantinum-vpn-start` | Запуск daemon с правильными зависимостями и каталогом |
| `~/.local/bin/serpantinum-vpn` | Команды оригинального CLI для этой копии оболочки |
| `$XDG_CONFIG_HOME/serpantinum-vpn/runtime.json` | Локальные пути Happ / Node.js, без токенов |
| `$XDG_CONFIG_HOME/serpantinum/settings.json` | Добавляется модуль VPN в правую часть панели |
| `$XDG_CONFIG_HOME/systemd/user/serpantinum.service.d/vpn-addon.conf` | Переопределение запуска shell |
| `$XDG_CONFIG_HOME/systemd/user/happ.service.d/vpn-addon.conf` | Автозапуск Happ, если не отключён флагом |
| `$XDG_STATE_HOME/serpantinum-vpn-addon` | Manifest, резервные копии, Nix GC roots |
| `$XDG_CACHE_HOME/serpantinum/vpn/locations.json` | Локальный кэш названий, адресов серверов и задержек, права 0600 |

По умолчанию XDG-каталоги — `~/.local/share`, `~/.config`, `~/.local/state`, `~/.cache`.
Если исходных user units нет, установщик создаёт их. Enable выполняется без `--now`.
Существующий shell и Happ продолжают работать до завершения вашей сессии.

Снимок содержит assets исходной оболочки и может занимать несколько сотен мегабайт.
Репозиторий и релиз содержат только overlay и установщик, а не весь Serpantinum.

## Первый запуск и автоподключение

Установка вступит в силу при следующем входе в графическую сессию.
Не выходите прямо сейчас, если текущую VPN-сессию нужно сохранить.
Это автозапуск после пользовательского входа, а не системный VPN до экрана логина.

При запуске Happ launcher устанавливает в `[Preferences]`:

```ini
AdvancedSettings\startMinimized=true
Subscriptions\subsConnectOnOpen=true
Subscriptions\subsConnectTypeOnOpen=lastused
```

Выбранный сервер и подписка не заменяются. Если Happ уже работает, launcher не
редактирует его настройки и не запускает вторую GUI. Не оставляйте параллельные
автозапуски Happ в compositor/XDG: клиент, запущенный раньше launcher, может пропустить
настройку автоподключения. Аналогично оставьте один способ запуска Serpantinum.

Если у вас уже правильно настроен Happ:

```bash
bash install.sh --no-happ-autostart
```

Для ручного запуска оболочки, когда обычная уже не работает:

```bash
~/.local/bin/serpantinum-vpn-start
```

Для сочетаний клавиш используйте `~/.local/bin/serpantinum-vpn msg toggle vpn`
и `~/.local/bin/serpantinum-vpn msg toggle guide`. Оригинальный Nix CLI может
принудительно выбирать каталог системной оболочки, поэтому у копии есть собственный CLI.

## Без systemd

```bash
bash install.sh --no-systemd
```

Этот режим создаёт snapshot и launchers, но не настраивает автозапуск Happ или службы входа.
В своём compositor замените существующий запуск `serpantinumd start` на
`~/.local/bin/serpantinum-vpn-start`. Не запускайте оба одновременно.
Автозапуск и автоподключение Happ настройте в самом клиенте и compositor.
Точная инструкция зависит от вашей init-системы и способа запуска сессии.

## Нестандартные настройки Happ

```bash
bash install.sh \
  --happ-config /path/to/Happ.conf \
  --happ-database /path/to/Happ/subs.db
```

При чтении SQLite используется `mode=ro`; база и подписки не изменяются.
Декодер получает зашифрованную запись через stdin и возвращает только поля списка серверов.
Кэш содержит адреса серверов и названия подписок: это локальные данные, их не надо
прикладывать к публичному issue. В репозиторий база, кэш и настройки пользователя не включены.

## Удаление и восстановление

```bash
bash install.sh --uninstall --dry-run
bash install.sh --uninstall
```

Удаление восстанавливает launch-файлы из backup, убирает добавленную запись VPN,
и отменяет enable только для служб, которые установщик включил сам.
Работающие процессы не останавливаются. При следующем входе используется обычный Serpantinum.
Если launch-файлы были изменены вами после установки, удаление остановится с указанием файлов.
Личные изменения `settings.json` сохраняются; если файл первоначально был symlink,
декларативную ссылку при необходимости восстановите через свой менеджер конфигурации.

Snapshot и backup сохраняются для работающей сессии и ручного восстановления.
После выхода из этой сессии можно удалить **только каталоги, указанные вашим manifest**.
Для повторной установки сначала уберите оставшийся snapshot/backup или используйте новые
`--target` и `--state-dir`. Если каталог уже существовал до установки, установщик
не станет принимать его за свою собственную установку и не удалит его.

Изменения трёх preference-ключей Happ сохраняются после удаления: это уже настройки
клиента, а не shell. Их можно вернуть в GUI Happ. Исходный `Happ.conf` сохраняется
как `Happ.conf.before-vpn-addon` при первом запуске launcher. Не заменяйте весь файл
старой копией без необходимости: с тех пор могли измениться подписки и выбранный сервер.
При восстановлении отдельных ключей сначала корректно закройте Happ в удобное время.

## Если что-то не работает

- **Несовместимый Serpantinum:** проверьте ревизию; используйте отдельный поддерживаемый checkout или ждите совместимый релиз.
- **Happ ELF не найден:** задайте `--happ-binary`; это не небольшой Nix wrapper и не путь к ядру Xray.
- **Локации недоступны:** проверьте версию/архитектуру Happ и наличие импортированной подписки. Новая база может быть несовместима.
- **Модуль не появился:** он загружается при следующем входе; проверьте переопределение через `systemctl --user cat serpantinum.service`.
- **Панель появилась, но статуса нет:** проверьте `runtime.json`, наличие Happ и пути процессов. Индикатор определяет процесс ядра, а не здоровье туннеля.
- **Кнопка не реагирует:** проверьте поддержку deep links `happ://connect` / `happ://disconnect` вашим клиентом. Непрерывная работа не тестировалась отключением во время разработки.
- **Пинг кажется слишком маленьким:** измеряется TCP connect через текущую маршрутизацию, иногда через локальный перехват VPN. Это не полноценный тест удалённого туннеля.
- **После rebuild исчез VPN из списка:** перенесите модуль в декларативные настройки Home Manager.

Для отчёта укажите дистрибутив, версии Serpantinum/Happ/Quickshell и текст ошибки установщика.
Не прикладывайте подписки, реквизиты серверов, `Happ.conf`, `subs.db` или личный settings.json целиком.
